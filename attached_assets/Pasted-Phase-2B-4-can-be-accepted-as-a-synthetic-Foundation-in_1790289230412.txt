Phase 2B-4 can be accepted as a synthetic Foundation integration, not a production Foundation connection. The next increment should expose the integrated capabilities through stable application APIs without adding UI or pretending unavailable capabilities are operational.

* Scope.

8. Idempotency and concurrency

At minimum assess:

* Evidence submission.
* Exception creation.
* Evaluation creation.
* Foundation synthetic refresh.
* Any exposed reconciliation operation.

Requirements:

* Use the application’s existing idempotency mechanism.
* Scope keys by operation and authoritative resource.
* Store or derive a request fingerprint.
* Same key plus same fingerprint returns the prior result.
* Same key plus different fingerprint returns an idempotency conflict.
* Concurrent identical requests must not create duplicate authoritative records.
* Failed attempts must follow an explicit retry policy.
* Immutable history must remain intact.
* Do not use process-local memory as the sole concurrency control.
