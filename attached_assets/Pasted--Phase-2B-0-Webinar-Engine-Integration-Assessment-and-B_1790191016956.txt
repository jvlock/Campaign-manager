# Phase 2B-0 — Webinar Engine Integration Assessment and Build Plan

Perform a read-only integration assessment for connecting the completed WEB-STANDARD-001 rule engine to the existing Campaign Manager application.

Do not implement persistence, migrations, routes, services, UI, external integrations, sending, publishing, or deployment in this phase.

The objective is to determine exactly how the completed in-memory engine should connect to the existing application without creating parallel models, duplicating business logic, or breaking current webinar functionality.

## 9. Persistence assessment

Determine what must be persisted versus recomputed.

Evaluate these categories separately.

### Source facts

Examples include event, occurrence, participant, registration, attendance, cancellation, waitlist, and operational delivery observations.

### Plans

Examples include recruitment plans, audience obligations, deadlines, and scheduled communication intentions.

### Evidence

Examples include QA reviews, governed observations, operational observations, source references, validity, and content-version scope.

### Evaluations

Examples include individual rule results, exception resolution, readiness-stage results, and completion results.

### Audit snapshots

Examples include exact standard version, evaluator-registry fingerprint, calculation instant, input references, and completion snapshot.

For each category, recommend one of:

* persist as authoritative state;
* persist as immutable history;
* persist only the source facts and recompute;
* cache with invalidation;
* compute on demand;
* do not persist.

Explain:

* business value;
* audit requirement;
* stale-data risk;
* recomputation risk;
* transaction boundary;
* versioning requirement;
* retention requirement.

Do not create schema changes.

## 12. Suppression integration

Determine where registration suppression must be enforced in the existing recruitment path.

The future implementation must ensure:

* registration immediately suppresses all future recruitment;
* cancellation suppresses later customer paths;
* internal and test records remain excluded;
* governed campaign exclusions remain non-bypassable;
* suppression occurs before any provider handoff;
* already-executed historical communications remain auditable;
* suppressed communications remain visible with reasons;
* retries remain idempotent.

Identify the exact existing service or function where this belongs.

Do not create external-send behavior.
