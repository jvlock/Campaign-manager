## Migration and persistence contract

New `0024_webinar_persistence_foundation.sql` follows `0001`–`0023` without editing them. It creates `webinar_persistence_bindings`, `webinar_persistence_records` and `webinar_persistence_audit`; campaign-safe composite FKs, nullable standard pair for unknown legacy identity, revision/idempotency/duplicate indexes, parent/release occurrence FKs, immutability triggers (including TRUNCATE), deferred required-audit trigger **and deferred graph checks** on records and bindings (contiguous revision, exact bound standard, typed parent/independent disposition actor, and snapshot release/standard/instant). Snapshot evidence/exception ID-array validation belongs to the repository, not those database triggers. `lib/db/src/schema/webinar-persistence.ts` exports the Drizzle mapping. Fresh 24-migration and full 23-to-24 upgrade tests passed: all 57 pre-existing table payloads byte-equal and zero fabricated legacy bindings; organizational fixture separately preserved 44 prior tables. No shared/production database migration, rollback rehearsal or customer data was performed. Main agent reports **successful explicit private `upgrade-0024`** for the checksum-matching synthetic cluster, followed by clean workflow restarts; it is not automatic `dev` upgrade. See runbook for stop/preinspection and no-reset rules. A fresh cluster receives 0024 in the ordered bootstrap. No parallel webinar event hierarchy is introduced.

`WebinarPersistence` is **internal only**: `append`, revision-paginated `load` with total/remaining/returned counts, and `retentionStatus` for isolated simulation/test data. No HTTP endpoint calls it; development simulation POST remains nonpersistent. Payload Zod schemas constrain opaque IDs/hash/status, not free-form comments, emails, URLs or copied participant PII. Source facts, plans, evidence, exception claims, snapshots and release records use distinct kinds; a readiness result never implies execution. Database graph triggers supplement repository validation; JSONB itself checks object shape rather than validating all domain fields, so privileged arbitrary SQL is not an operational evidence-ingestion path. Audit rows cannot silently disappear through ordinary UPDATE/DELETE/TRUNCATE; retention expiry is metadata, not permission to purge. Legal-hold status derives from latest immutable hold/unhold event; deletion remains disabled.
