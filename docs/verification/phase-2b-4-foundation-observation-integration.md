## Internal provider contract, request construction and validation

`GovernanceFoundationProvider` is an internal server-side `request(input, AbortSignal)` interface with a synthetic environment and declared service/taxonomy versions. `SyntheticContractAdapter` accepts an explicitly supplied fixture callback. No fixture is registered by default: `bootstrapKnownSyntheticFixture()` registers the narrow, main-agent-approved synthetic fixture only with `GOVERNANCE_SYNTHETIC_CONTRACT=enabled` in open-development mode, never on deployment. The known fixture returns a **synthetic taxonomy `webinar` classification only**, with service version `synthetic-contract-v1`, taxonomy version `synthetic-fixture-v1`, validity 2025–2030 and fixture provenance; internal title, campaign code, UTM, objective membership and exclusion return explicit unavailable results. There is no locally generated substitute for those outputs. This is not an external network connector or Foundation-owned versioned API.

The **Campaign Manager synthetic contract v1** request is strictly parsed: `contract="campaign-manager-synthetic-contract-v1"`, type (`taxonomy`, `internal_title`, `campaign_code`, `utm`, `objective_membership`, `campaign_exclusion`), `environment="synthetic"`, UUID scope (`campaignId`, `activityId`, `occurrenceId`, nullable `communicationId` and `destinationId`), normalized input, SHA-256 input fingerprint and deterministic `cm-<fingerprint>` request reference. Inputs include activity type; optional explicit objective/product family/audience/geography/industry/channel/communication type/content/language IDs, event date and optional destination URL. The UTM request distinguishes `missing`, `ambiguous`, `invalid`, `valid` and `not_applicable` destination states; invalid destination requests are shown unavailable and are not invoked. Other absent or nonconforming optional IDs normalize to null: the entire real Foundation input contract and missing-versus-empty semantics remain unknown. The builder reads stored stable IDs and scoped application communications/destinations, not display labels or participant records. HTTPS destinations are checked for credentials and secret-like query keys. Fingerprint serialization sorts object keys and includes typed scope and input; same normalized input gives the same hash, changes to included governed input a different hash.

The strict synthetic response schema requires status (`success`, `unavailable`, `error`, `partial`), exact type/environment/scope, service ID/version, taxonomy version, matching request reference/fingerprint, response/valid-from/optional expiry timestamps, deprecation flag, synthetic adapter provenance reference, bounded allowlisted warnings/structured errors and one typed output or null. Outputs are classified taxonomy IDs/labels, title/components, simulated campaign code/reservation, structured UTM parameters plus URL, objective-membership decision and campaign-exclusion decision. Validation caps serialized response at 32 KiB, rejects unknown fields, scope/type/reference/fingerprint mismatch, unsupported versions, inconsistent timestamps or validity, expiry, deprecation, partial/incomplete success and missing provenance. It validates **two clocks**: the immutable evaluation `calculationAt` (as-of) and the actual transport `receivedAt`. A response may legitimately arrive after as-of but not in the future relative to its receipt; both as-of and receipt must satisfy the asserted validity window. History replay verifies the original receipt and also checks current expiration. Taxonomy IDs must appear among supplied selected IDs; objective/audience decisions must match request IDs; UTM URL must preserve destination origin/path/fragment and non-UTM query and contain exactly the governed parameters, without duplicate query keys. These checks apply only to the local synthetic schema; no real Foundation signature/trust or production catalog has been evidenced.

`objective_membership` and `campaign_exclusion` are modeled as independent fixture response types **but are intentionally not mapped into evaluator subcontexts**. A per-activity objective/exclusion decision cannot replace the complete, source-scoped canonical population and governed exclusion evidence. `WEB-SETUP-003`, `WEB-REC-010` and related readiness/QA dependencies remain unavailable rather than receiving a fabricated favorable decision.

The **deterministic test provider** exercises valid responses for all six synthetic contract types, along with malformed, incomplete, mismatched, expired, deprecated and error cases; this test-only provider is distinct from the configured development fixture, which deliberately returns just the known `webinar` taxonomy result. Passing a synthetic response-schema test is not evidence of an actual Foundation-owned response.

## Failure, retry, persistence and cache decision

| Condition | Current server-side disposition |
|---|---|
| No provider configured | Observation unavailable with `not_configured`; no fixture or empty success is invented. |
| Unreachable, timeout, rate limit, internal provider error | Structured reason; at most three attempts per request; 1.5-second timeout and bounded backoff, rate-limit hint capped at 2 seconds. Same deterministic request reference is reused. |
| Authentication, authorization, invalid request, malformed/partial response, fingerprint/scope/environment/version error, deprecation, expiry, conflict | Distinct failure reason where identifiable; no blind retry of nontransient validation/security errors; no accepted observation for that request. |
| Existing history | Revalidate scope, fingerprint, environment, configured synthetic service/taxonomy versions, release fingerprint and validity before reuse. Changed input/version/release or expired/deprecated output is not current. Read-only inspection distinguishes available, unavailable, stale, expired and deprecated. No in-memory cache exists. |

**Cache decision:** no separate in-memory or external cache. The local reuse of immutable history **does behave as a bounded cache**: eligibility includes observation type, input fingerprint, service and taxonomy versions, synthetic environment, release fingerprint and validity/expiration against both as-of and current time. It retains original response/provenance and receipt timestamp; explicit refresh invokes the provider, still rejecting conflicting outputs under the same input/versions. History cannot substitute for a configured provider, cannot serve production data in open development, and is not independent Foundation authority. The actual Foundation contract must specify whether any rule requires fresh results and whether this reuse is permissible; no Foundation-owned cache semantics are asserted.

Accepted fixture responses are appended under the existing Phase 2B-1 `webinar_persistence_records` `kind="source"` / `sourceType="foundation"` path, with strictly validated JSONB receipt payload (request, response, release fingerprint, supersedes ID, received time, retry count, simulation-only flag). The 0024 immutable record/audit and occurrence revision/transaction boundary are reused; there is **no parallel results table, no migration 0026, and all 25 migrations remain byte-identical**. The append idempotency key binds contract/type/scope/environment/versions/release/request/response; same-current-output reuses the prior immutable record, conflicting output for identical input and versions fails even if the earlier receipt expired, and superseding a prior record retains history. Same-occurrence transaction locking serializes concurrent resolutions; synthetic campaign-code duplicate checking holds a global transaction advisory lock keyed by the code across occurrences while querying and appending. This is a synthetic safeguard, **not** proof of Foundation-issued production uniqueness. Retry count/final failure are exposed in diagnostics without copying provider exception messages; no unbounded background retry loop exists. Source facts, governed receipt and evaluation snapshot remain separate.

## Orchestration, readiness and UI boundary

The sole existing Phase 2B-2 orchestration path loads the occurrence source snapshot, resolves/validates synthetic observations inside the occurrence transaction, reloads and checks changed sources, assembles canonical input, maps separately accepted naming/code/taxonomy/communication UTM outputs to the relevant legacy evaluator evidence slots, evaluates the unchanged canonical 106-rule registry and writes a new simulation-only release/readiness snapshot with Foundation receipt source references and exact versions. Refresh is **an orchestration command**, not an observation-only write. The snapshot input fingerprint incorporates persisted governed request/response/release identity, so changed receipts affect subsequent immutable snapshots; request-local diagnostics distinguish unavailable observations. The same fixed request/calculation/release/idempotency identity replays without advancing the revision. Historical snapshots retain source references and their versions. Evaluators are pure; no Foundation call originates from an evaluator. The mapping **does not** promote objective/exclusion decisions; missing complete canonical subcontexts remain missing. A taxonomy receipt alone does not fill title, code or UTM output. A synthetic source label `foundation` in an evaluator slot is not evidence of an external Foundation call.

Inspection states are separate: evaluator implemented, observation available, connector configured, connector reachable **on this request**, and live production connection. `connectorReachable` reflects only a validated fixture call in the resolving request; read-only GET inspection does not call the provider and correctly reports reachable false even when a valid immutable observation is available. Live production connection is false. The development-only GET inspection and POST refresh routes scope-check an eligible synthetic occurrence, expose governed output/status, versions/fingerprint/reference/provenance, separate response and receipt timestamps, expiry, affected rule IDs and simulation-only status; refresh without a configured fixture returns an explicit conflict. GET uses the latest readiness snapshot's fixed calculation instant to reconstruct the release digest, rather than inventing a new one on every inspection. The UI labels the contract synthetic-only, separates configuration from validated calls/history, exposes a refresh action only for configured fixture mode and has no manual governed-result entry. It must never say “Foundation connected” merely because a fixture is configured or a historical receipt exists.

Security boundary is a server-only opt-in, synthetic environment schema/registration restriction, deployment guard, bounded request/response shapes and timeout, scoped source loading and exclusion of participant records from constructed requests. The development policy admits only inspection/refresh routes and rejects guessed connect/credential routes or user-provided provider URLs, outputs and actor IDs; no browser secret or direct Foundation call is involved. Safe error codes do not copy provider exception text. These are implementation safeguards, **not** proof of production identity, remote TLS/auth configuration or external endpoint isolation. Production endpoints and credentials remain absent; no customer/participant data, secrets, live send or publish is authorized.
