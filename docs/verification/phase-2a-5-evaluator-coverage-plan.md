## 5. Primary classifications

Primary classification identifies the main evaluation dependency, not an exclusive evidence source. In particular B can also require manual review and external delivery evidence; these secondary dependencies are explicit in the matrix. A requires sufficient **current typed E context**, not a field that merely exists in another module. No missing rule here meets that strict standard. C means an uncontroversial typed addition; F means external observations are central to the conclusion.

G has no assigned missing rule: containment tests remain important but no missing session rule is satisfied solely by “there is no sending function.” A future G reporting adapter could expose a version-bound structural assurance, but must not be counted as a newly implemented session evaluator merely for returning a static pass. H covers D1's canonical completion tension, D2's undefined materiality/promptness, and D3's unspecified attended deadline anchor, not unavailable services, missing schemas or ordinary human judgment. A verified planner proves its implemented convention, not that an undefined canonical business policy has been settled.

## 6. Result semantics

E currently supports `pass`, `fail`, `not_applicable`, `unimplemented`; reasons include `missing_evidence`, but that reason currently accompanies failure. Minimum proposed change: add **`evidence_unavailable`** to the status union and permit it in `RuleFinding`; retain `missing_evidence` as a reason. Keep `unimplemented` to mean **evaluator unavailable** rather than renaming it. R result validation/aggregation and tests would then need to understand unavailable evidence as unresolved, not a pass. No type is changed here.

Common requirements: pass needs current, sufficiently complete evidence proving the rule; fail needs evidence proving a violation; NA needs affirmative evidence that the canonical trigger is false. Unknown applicability is unavailable. Explicitly missing required data in a complete authoritative snapshot can establish a canonical absence violation (for example an empty required title). Missing connector output, partial arrays or an unobserved send cannot. Invalid/stale/cross-event/version-mismatched evidence cannot support pass. Every class retains `unimplemented` when its registry evaluator is absent, even if a planner/manual record exists.

“Resolved by exception” stays a separate X/R resolution linked to the **original failed finding**, scope and originating stage. It is not a new evaluator status and never converts fail into pass. Existing exception eligibility and blocker classification remain authoritative. A missing evaluator is always missing coverage; service unavailability remains unresolved/non-bypassable; advisory outcomes retain their canonical type. An unresolved unavailable result is not authority to recruit/run/follow up/complete.

Timing rules using “sent” or “delivered” require real observed evidence even if U supplies an exact due instant. Planning-only success can be reported separately as configuration diagnostics, never as full rule pass. No new sending integration is proposed or authorized in this phase.

## 7. Reusable manual evidence design

Proposed in-memory type only; no persistence, authentication, upload or UI:

```ts
type ManualEvidence = Readonly<{
  evidenceId: string; // immutable identifier; reject duplicate mutation
  ruleId: RuleId;
  standardId: "WEB-STANDARD-001";
  standardVersion: "1.0-pilot-rc1"; // exact catalog version
  evidenceStatus: "confirmed" | "rejected" | "incomplete" | "unavailable";
  evidenceDescription: string;
  suppliedBy: Readonly<{ nameOrPilotIdentifier: string; identity: "unverified" }>;
  suppliedAtEpochMs: number;
  sourceReference: string | null;
  attachmentReference: string | null; // reference only, no upload capability
  validFromEpochMs: number | null;
  expiresAtEpochMs: number | null;
  notes: string;
  scope: Readonly<{
    eventId: string;
    participantIds: readonly string[];
    communicationIds: readonly string[];
    deliverableIds: readonly string[];
  }>;
  binding: Readonly<{
    inputSnapshotVersion: string;
    artifactVersion: string | null;
    reviewedAtEpochMs: number;
    snapshotCompleteness: "complete" | "partial" | "unknown";
    observationFromEpochMs: number | null;
    observationThroughEpochMs: number | null;
  }>;
}>;
```

Validate IDs, nonblank description/supplier, finite ordered timestamps, no future supplied/review time relative to caller observation, validity window where applicable, exact standard/rule membership, event/participant/communication ownership, and snapshot/artifact version. `Readonly` is compile-time only: validation must defensively copy/freeze or reject identifier reuse with changed content. Empty scoped arrays do not mean “all”: the owning evaluator must know the asserted scope/inventory and completeness. No arbitrary universal expiry period is invented; explicit expiration and any relevant input/artifact change invalidate reliance. Lack of a source/attachment is allowed only when that rule's attestation itself is sufficient; recording inclusion, page tests and actual sends require the underlying referenced evidence.

Rule quality remains specific: speaker participation differs from materials receipt; a document's existence differs from readiness; a CTA differs from objective suitability; a waitlist state differs from visibility; recording expectation differs from actual availability; approved neutral content differs from delivery. Human confirmation uses unverified pilot identity and cannot claim authenticated approval. “Confirmed” is not a generic pass switch. Evidence supports a finding; an exception resolves an eligible failed blocker separately.
