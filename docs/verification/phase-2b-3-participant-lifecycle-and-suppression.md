## Transition matrix and integration path

```text
explicit new-synthetic campaign / Activity / occurrence + exact binding
  → generated fixture identity and provenance (no customer import)
  → validated source event and projected registration/attendance or session change
  → append-only future obligation/suppression history (past seeded execution immutable)
  → Phase 2B-2 single orchestration boundary / canonical audience planner
  → immutable occurrence-scoped readiness simulation snapshot
  → simulation-only inspection; no provider handoff exists
```

| Action | Precondition → state change | Distinction and failure boundary |
|---|---|---|
| `register` | New or explicitly cancelled registration + open/scheduled occurrence → registered | First registration instant retained, future recruitment suppressed, valid reminders recalculated. Re-registration is explicit, not automatic after cancellation. |
| `waitlist` | Not registered + open/scheduled occurrence → waitlisted | Not a registration confirmation; recruitment suppressed, no registrant-only reminders. |
| `promote` | Waitlisted + open/scheduled occurrence → registered | Explicit idempotent transition, no invented automatic capacity admission. Reminder plan recomputed. |
| `cancel-registration` | Registered + attendance unknown → cancelled registration | Event remains unchanged; first registration timestamp/history retained; future customer paths suppressed, not returned automatically to recruitment; never labels the person absent. |
| `record-attendance` | Confirmed registered + completed occurrence + attended/absent observation → per-person result | Requires an observed actual event end for completed populated occurrence. Conflicting result leaves projection unknown; source events survive for reconciliation. |
| `reconcile-attendance` | Existing attendance observation + completed occurrence + confirmed registration → corrected per-person projection | Separate source event; explicit source reference and audit rather than silent correction. Unknown without a source record is distinct from explicit absence. |
| `cancel-occurrence` | Not already completed/cancelled → cancelled event | Does not cancel participant registrations. Future recruitment/reminders/follow-up suppressed; previously executed history preserved. No cancellation notice is sent. |
| `reschedule` | Upcoming draft/open/scheduled occurrence + changed valid local date/time/IANA zone → same occurrence, new schedule | Local instant is validated by Temporal; old schedule is in event payload. Replanning must not move already-executed communications; overdue/invalid obligations require review, not silent execution. |
| `complete-occurrence` | Scheduled/in-progress + observed synthetic actual end after start and no later than calculation time → completed | Not individual attendance; unknown remains unknown until per-registrant observation or explicit reconciliation. |
| Internal-only `seed-executed-history` | Confirmed fixture registration + past instant + configured canonical communication and synthetic message UUID → immutable prior synthetic history | Seeds a **pre-existing fixture fact**, not a send or provider event. Excluded from HTTP action choices; repeated/different message conflicts. Later replanning cannot rewrite it. |

`checkSyntheticTransition` rejects prohibited combinations and uses an exhaustive action switch. Event cancellation prevents later participant or schedule transitions; duplicate source-event references with different requests conflict rather than alter history. Planned follow-up: attended → attended variant; explicit absent → absent variant; unknown → reconciliation first, neutral only after the canonical two-business-day threshold **and** approved neutral variant. Current synthetic planner sets `neutralVariantApproved:false` and `followUpAssetId:null`; 2B-0A approves only the concept, not customer-facing copy. Cancelled/internal/test persons have no customer follow-up path. No follow-up is sent.

## Atomicity, idempotency, suppression and synthetic guard

`transitionParticipantLifecycle` uses `WebinarPersistence.withEvaluationTransaction` with an occurrence lock and expected revision. It checks exact synthetic eligibility; fixture/person campaign, optional audience branch and occurrence scope; current projection and immutable history; nondecreasing observation chronology; action-specific fields and time. **The branch is an existing domain filter, not authenticated group authorization.** In one transaction it inserts the unique `(session,event_key)` and `(session,source_system,source_reference)` event, updates existing registration/attendance/session projection as applicable, appends future obligation history, invokes `simulateWebinarInTransaction` (not individual evaluators), and links the resulting snapshot(s). 0025's deferred trigger requires exactly one same-actor, occurrence-scoped nonoperational readiness snapshot for a per-person event; occurrence-wide events require one snapshot for **each** enrolled synthetic person, or one null-person snapshot when empty. Replays return persisted IDs; a changed request under a reused key/reference conflicts. Same-occurrence updates serialize and stale revisions conflict. Database tests are reported passing below; fixture creation is separately scoped and is not itself a lifecycle snapshot transition.

`planSyntheticPopulation` reuses the canonical audience planner; `decideSyntheticSuppression` emits evaluated timestamp, participant/occurrence/nullable communication ID, reason and explanation, source references, release fingerprint and `simulation-only`. It never authorizes a customer handoff (no provider boundary was added). Execution history is immutable; future obligation rows skip seeded executed communications. `loadOccurrenceSources` takes one MVCC source snapshot; internal occurrence-wide planning loads the **whole** enrolled synthetic population without page limit. `listParticipantSimulation` and `listSyntheticFixtures` instead expose explicitly partial sorted pages with `total`, `returned`, `nextOffset`, `nextCursor` and optional domain branch filter. The UI labels partial pages and never treats the visible page as a whole-population transition. No manual free-text bypass or invented governed receipt is valid.

`fixture-[0-9]{1,8}` is the only supplied fixture identifier; SHA-256 of campaign ID and fixture key yields a stable synthetic UUID, and email display is derived as `fixture-…@participants.test`. Inserted `webinar_people` have `is_synthetic=true` and a generated label. Database fixture provenance is fixed to `synthetic-participant-simulator`, with campaign/person FK and unique fixture key. Existing fixtures with mismatched audience settings conflict. The source loader only selects enrolled fixture-linked people; an unenrolled person is explicitly checked against fixture, synthetic flag, generated label and campaign before use. Closed input schemas reject supplied customer identifiers, arbitrary emails, names and import payloads. Explicit fixture creation is an **owner-approved narrow exception** to Phase 2B-2's deliberate nonquery of participant rows, not permission to use real PII. These guards do **not** turn development actor/branch IDs into authenticated customer operators or permit real data. No operational approval, provider handoff, customer data, production authentication, deployment or real sending is authorized.

## Why migration 0025 is needed, and what it does not do

Phase 2B-0 assessment §§3.2, 5.1, 6–7, 9–10 explicitly identifies that `webinar_registration_results` and `webinar_attendance_results` are **current projections only**: neither can store waitlist/cancellation/unknown or source-event/correction history, and `webinar_sessions` has no occurrence status history. `0024` persistence JSONB stores simulation/evaluation records, not a constrained per-person source-event ledger or append-only reasoned obligation history. These are the exact accepted 2B-3 gaps; adding columns to the old constrained projection or inventing a parallel participant/attendance authority would discard either legacy semantics or history. `0025_webinar_synthetic_lifecycle.sql` adds only fixture provenance, immutable scoped lifecycle source events, append-only reasoned obligation history, fixture-seeded prior execution evidence and event→snapshot links beside the **same** `webinar_people`, registration and attendance projection tables.

Migration constraints include campaign/person/session composite FKs, closed action/communication/disposition DB checks, action/person and attendance/actual-end checks, unique fixture and idempotency/source-reference keys, person-history/current-obligation indexes, execution-source matching, append-only triggers and deferred same-actor exact-population snapshot linkage. `webinar_synthetic_executions` stores immutable past synthetic fixture facts only, never a live send. Main verifier reports fresh disposable application of all **25 migrations**, `0023`→`0024` preservation of **57** prior tables and `0024`→`0025` preservation of **60** prior tables without history backfill; independent organizational preservation covered **44** tables. Cleanup of `/tmp/disposable-pg-p8KW4K` was confirmed (process/socket/root gone). 0025 was applied only to the verified isolated private synthetic database through its guarded launcher, not shared/production, and no `db push`. These results are attributed to the main verifier, not rerun by this documentation author.
